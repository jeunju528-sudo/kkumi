# docs 지식 저장소

은주와 에이전트가 같은 기억을 공유하기 위한 문서 모음. 결정의 이유, 실패한 시도, 도메인 지식을 여기에 남긴다.
새 문서를 만들거나 기존 문서를 고칠 때는 이 문서의 구조와 작성 규칙을 따른다.

## 구조

```
docs/
├── README.md              # 이 문서 (구조, 작성 규칙, 양식)
├── progress.md            # 진행 현황 (세션 시작 시 먼저 확인)
├── design.md, ui-spec.md  # UI 기준 (화면 구현 전 확인)
├── troubleshooting.md     # 해결한 에러 기록 (면접용)
│
├── decisions/             # 기술 결정 기록 (ADR)
│   ├── README.md          # 목록, 다음 번호, 미정 항목
│   ├── _template.md
│   └── 001-ci-cd-github-actions.md ...
│
├── conventions/           # 코딩 규칙 상세 (올바른 패턴 / 금지 패턴)
│   ├── backend.md
│   ├── frontend.md
│   └── testing.md
│
├── domain/                # 비즈니스 도메인 지식
│   ├── glossary.md        # 용어 사전
│   └── workflows.md       # 주요 업무 흐름
│
└── failures/              # 실패 기록 (시도했다가 포기한 방법)
    ├── _template.md
    └── 001-figma-design-copy.md ...
```

## 어디에 쓰나

| 상황 | 위치 |
| --- | --- |
| 방식 A와 B 중 하나를 골랐다 | `decisions/` |
| 시도해봤지만 포기했다 | `failures/` |
| 에러를 만나 해결했다 (방법은 그대로 유지) | `troubleshooting.md` |
| 비즈니스 규칙, 용어, 업무 흐름이 정해졌다 | `domain/` |
| 코딩 규칙과 예시를 추가한다 | CLAUDE.md + `conventions/` |
| 진행 상황이 바뀌었다 | `progress.md` |

헷갈리면 이렇게 구분한다.
- 결정: 선택지가 둘 이상이고 하나를 골랐다. 고른 길은 계속 간다.
- 실패 기록: 길을 가봤는데 포기했다. 다시 가지 않는다.
- 트러블슈팅: 길은 그대로이고 도중에 만난 에러를 해결했다.

## 작성 규칙

공통
- 파일명은 `NNN-kebab-case.md`. `decisions/`와 `failures/`는 각각 001부터 순서대로 번호를 붙이고, 번호는 재사용하지 않는다
- 양식은 각 폴더의 `_template.md`를 복사해서 쓰고, 섹션을 빼지 않는다
- 문체는 짧은 명사형·평서. 이유와 장단점은 근거가 있는 것만 쓴다. 근거가 없으면 "기록 없음"이라고 적고 지어내지 않는다
- 날짜는 `YYYY-MM-DD`. 이 구조로 옮기기 전에 내려진 결정은 레포에 기록된 날짜(2026-10-03)로 표기한다
- 결과(ADR)와 에이전트 지침(실패 기록)에는 "~하지 않는다" 형태의 구체적인 행동을 쓴다. 에이전트가 읽고 행동이 달라져야 하기 때문이다

결정 기록(`decisions/`)
- 한 결정이 파일 하나. 상태는 `확정` / `미정` / `검토 중` / `폐기 (대체: NNN)` 중 하나
- 확정된 결정은 고치지 않는다. 번복하려면 먼저 은주와 논의하고, 새 ADR을 쓴 뒤 기존 ADR의 상태를 `폐기 (대체: NNN)`으로 바꾼다
- 결정을 추가하거나 상태를 바꾸면 `decisions/README.md`의 목록과 "다음 번호"도 함께 고친다
- 아직 정하지 못한 질문은 ADR로 만들지 않고 `decisions/README.md`의 "미정"에 적는다

실패 기록(`failures/`)
- 시도한 날짜, 시도한 이유, 실패 원인, 현재 대안, 에이전트 지침을 모두 쓴다
- 비슷한 시도를 하기 전에 먼저 이 폴더를 확인한다

도메인(`domain/`)
- `glossary.md`와 `workflows.md`는 CLAUDE.md "도메인 규칙 (확정)"의 상세판이다. 규칙이 바뀌면 셋을 같이 고쳐서 서로 어긋나지 않게 한다

코딩 규칙(`conventions/`)
- 규칙을 추가·변경하면 CLAUDE.md와 예시를 같이 고친다. 코드로 강제할 수 있으면 `ArchitectureTest` / `eslint.config.js`에도 반영한다 (`decisions/006`)

## 에이전트 작업 절차
1. 작업 전에 관련된 `decisions/`, `failures/`, `domain/glossary.md`를 확인한다
2. 결정 지점(A vs B)이 생기면 ADR 추가를 제안한다. 은주가 승인하면 `확정`으로 쓴다
3. 시도했다가 포기하면 `failures/` 추가를 제안한다
4. 에러를 해결하면 `troubleshooting.md` 추가를 제안한다
5. 문서 변경은 코드 변경과 같은 PR에 포함한다
