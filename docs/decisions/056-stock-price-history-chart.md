# 056. 종목 상세 차트: 분봉(1분 기록 24시간 보관) + 일봉(OHLC 영구 보관)

## 상태
확정 (2026-11-12)

## 배경
- 종목 상세(사기·팔기) 차트가 화면에 들어온 뒤의 가격만 최대 30개(약 2분 반) 찍어서, 들어가자마자 보이는 정보가 현재가와 오늘 등락률뿐이었음
- 050에서 종목 유형·평소 가격을 숨기기로 해서, 플레이어가 스스로 판단할 재료는 가격 흐름밖에 없음. 개발자가 직접 플레이해 보니 무엇을 살지 고를 수 없었음
- 서버는 현재가·오늘 시작가만 보관해서 과거 가격을 계산으로 되살릴 수 없음
- 처음에는 같은 1분 기록을 "1시간 | 1일" 탭으로 확대만 다르게 보여주려 했으나, 개발자 리뷰에서 "같은 데이터를 탭으로 나눌 이유가 없다"는 지적 → 데이터 단위가 다른 분봉·일봉으로 변경

## 결정
- 분봉: 1분마다 도는 현재가 저장(040, `saveSnapshot`)에서 종목별 현재가를 `stock_price_history`(종목 코드, 가격, 기록 시각)에 1행씩 추가. 매일 3시 30분(KST)에 24시간 지난 기록을 벌크 delete(`@Modifying`) → 테이블에는 항상 24~48시간치
- 일봉: `stock_daily_candle`(종목 코드, 날짜, 시가·고가·저가·종가, (종목 코드, 날짜) 유니크)에 같은 1분 저장 때 오늘 일봉을 증분 upsert. 그날 첫 기록이면 시가 = 오늘 시작가로 생성, 이후 고가·저가를 넓히고 종가 교체(변경 감지). 삭제 없음
- API: `GET /api/stocks/{code}/prices`(최근 24시간 1분 기록 전부), `GET /api/stocks/{code}/candles`(오늘 포함 최근 30일). 둘 다 오래된 순, 없는 종목은 404 `STOCK_NOT_FOUND`
- 화면: 탭 "분봉 | 일봉". 분봉은 1분 기록 + 지금 가격(5초 갱신)을 오른쪽 끝에 이은 선, 일봉은 캔들(심지 = 고가~저가, 몸통 = 시가~종가, 오르면 빨강·내리면 파랑) + 오늘 캔들에 지금 가격 반영. 둘 다 1분마다 다시 받고, 모자라면 오른쪽 정렬. 차트 아래 시간 축 3칸과 보고 있는 탭의 최고·최저가
- 멈춤 뒤 몰아서 실행 방지 (2026-11-12 로컬에서 PC 절전 후 확인: 10분 기록 0개 → 5초 사이 9개, 가격이 2초 만에 10분치 움직임)
  - 1분 기록 시각은 분 단위(`22:45:00`)로 자르고, 같은 분 기록이 이미 있으면 1분 기록만 생략 (현재가·일봉은 갱신). `recorded_at` 단독 인덱스 추가(같은 분 확인, 3시 30분 삭제)
  - 5초 시세 갱신(`tick`)과 평가액 푸시를 `fixedRate` → `fixedDelay`. 멈췄다 풀려도 밀린 실행을 몰아서 하지 않음. 1분 저장은 `fixedRate` 유지(분 단위 기록 간격이 밀리지 않게)
- 작성 분담: 개발자 요청으로 이번 기능은 프론트 동작(api, hooks, 차트 데이터 연결)까지 에이전트가 작성하고 개발자는 리뷰와 로직 설명으로 이해 (045의 예외, 새 기술 없음이 조건)

## 이유
- 분봉 24시간은 지금 흐름(빠지는 중·오르는 중)과 하루 흐름을 한 화면에, 일봉은 평균 회귀 반감기(12시간, 029)보다 긴 범위라 "평소보다 싼지"를 가격 흐름만으로 짐작 가능. 평소 가격 자체는 050대로 숨김
- 분봉·일봉 탭은 증권사 앱과 같은 구성이라 실제처럼 보이고, 휴대폰에서 탭만 누르면 됨
- 일봉을 1분 저장 때 바로 갱신하면 일봉 배치가 따로 없어서, 3시 30분 분봉 삭제와 순서가 꼬일 일이 없고 재시작 뒤에도 이어서 갱신됨. 오늘 캔들이 실시간으로 자람
- 원본(1분 기록)은 하루만 두고 묶은 값(일봉)만 오래 남기는 방식이라 저장량이 일정: 분봉 하루 28,800행(20종목 × 1,440분), 일봉 하루 20행
- DB 저장이라 배포(재시작) 뒤에도 차트가 이어짐. 이미 1분마다 도는 저장 트랜잭션에 얹어서 스케줄·쓰기 시점이 늘지 않음
- 실제 시장도 시스템이 멈춘 동안의 체결을 나중에 만들어내지 않고, 분봉은 체결 시각의 분으로 묶어 분마다 1개. 몰아서 실행된 갱신은 멈춘 시간만큼의 가격 변동을 몇 초에 몰아 만들어 가짜 급등락이 생김
- 종목과 연관관계 없이 코드만 저장: 조회 조건이 코드와 시각·날짜 범위뿐이라 join 불필요

## 포기한 대안
- 같은 1분 기록을 "1시간 | 1일"로 확대만 다르게: 구현 쉬움 / 같은 데이터를 탭으로 나눠 의미 없음 (개발자 리뷰)
- 하루치 가로 스크롤(1분 4px, 약 5,760px): 1분 단위로 다 보임 / 휴대폰에서 페이지 스크롤과 손가락 동작이 겹치고, 세로 폭 기준을 정하기 어려움
- 일봉을 매일 0시 배치로 생성: 원본에서 한 번에 계산 / 배치 시각과 분봉 삭제 시각 순서에 의존, 오늘 캔들이 하루 끝까지 안 보임
- 메모리 링 버퍼(종목별 최근 기록): DB 쓰기 없음 / 배포마다 차트 초기화
- 5초 틱마다 기록: 촘촘함 / 하루 345,600행, 화면에서 구분 안 됨

## 결과
- 1분 기록의 고가·저가는 그 1분 마지막 가격 기준이라, 1분 안에서 튄 가격은 일봉 고가·저가에 안 잡힐 수 있음 (5초 틱 전부 기록하지 않은 대가)
- 기능을 켠 날부터 쌓임: 분봉은 24시간 뒤, 일봉은 30일 뒤에 꽉 참. 서버가 꺼져 있던 구간은 비어 있음
- 0시 직후 1분 동안은 서버 오늘 일봉이 아직 없어서, 화면의 실시간 가격이 어제 캔들에 잠깐 반영될 수 있음 (다음 1분 저장 때 정상)
- 이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 종목 유형·평소 가격(050에서 숨김)을 차트에 표시하지 않는다.
