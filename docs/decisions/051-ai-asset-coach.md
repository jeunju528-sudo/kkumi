# 051. AI 자산 코치: 런칭 후 추가, Spring AI + Gemini, 호출 한도는 Redis

## 상태
확정 (2026-11-10)

## 배경
- 채용 관점 피드백(2026-11-09): 프로젝트가 취미처럼 보이고, 이력서에 AI 관련 내용이 거의 없음. 새 프로젝트보다 기존 프로젝트 개선 권장
- 자연어 질문에 LLM이 조회 전용 tool을 호출해 실제 서버 데이터로 답하는 "AI 자산 코치" 추가 결정. 숫자는 서버가 계산하고 AI는 해석만 함
- 상세 설계: 노션 "9. AI 자산 코치 설계" (범위, tool 3개, 보안, 숫자 검증, 감사 로그, 평가셋)
- 024(새 기술 상한선)에서 금지한 Redis·Kafka 도입 여부를 같이 정해야 함

## 결정
- 일정: 11/14 런칭 후 착수, 하루 1~2시간 × 약 2주. MVP 범위와 런칭 일정은 그대로
- 범위: 조회 전용 tool 3개(포트폴리오 요약, 거래 요약, 아파트 추천), 실행 tool 없음, userId는 서버 세션에서 주입. RAG·멀티턴·스트리밍 제외
- LLM 연동: Spring AI 2.0 + Gemini. tool 자동 실행은 끄고 호출 루프를 직접 제어 (질문당 tool 호출 최대 횟수, 화이트리스트 확인, 감사 로그)
- 공급자 추상화: 직접 만든 LlmClient 대신 Spring AI `ChatModel` 사용, 테스트용 가짜 모델만 작성
- 호출 한도: RateLimiter 인터페이스 + Redis 카운터 구현체 (024의 예외)
- 숫자 검증: 자리표시자 치환(LLM은 `{{totalValue}}` 같은 자리만 쓰고 서버가 tool 결과로 채움) 우선, 정규식 대조는 보조. 구현 단계에서 확정
- Kafka: AI 코치 완료 후 연습용으로 도입 (024의 예외). 붙일 위치(감사 로그 이벤트 발행 후보)와 도입 근거는 그때 별도 ADR

## 이유
- 기존 거래·평가액·추천 데이터 위에 올리는 기능이라 "기존 프로젝트 개선" 방향과 맞음
- 목표 기업(금융 IT·핀테크) 관점에서 "AI를 안전하게 붙이는 백엔드"(권한 주입, 실행 차단, 숫자 검증, 감사 로그)가 면접 소재로 강함
- Spring AI: Java/Spring 채용 공고에서 인지도가 높음. 2.0이 Spring Boot 4.0/4.1 기준이라 현재 버전(4.1.1)과 맞음
- tool 자동 실행을 끄면 프레임워크를 쓰면서도 호출 흐름이 코드에 드러나 직접 설명 가능
- Redis: 카운트 증가와 만료(INCR, EXPIRE)가 원자적이라 동시 요청에도 정확하고, 재시작·서버 증설에도 한도 유지. 인터페이스로 분리해 메모리 구현으로 교체 가능

## 포기한 대안
- RestClient로 Gemini 직접 호출: tool calling 프로토콜 이해에 유리 / 시장 인지도는 Spring AI가 높음. 자동 실행을 끄는 방식으로 이해도 보완
- 직접 만든 LlmClient 인터페이스: 공급자 교체 설명에 유리 / Spring AI `ChatModel`과 역할이 겹침
- 메모리 카운터 RateLimiter: 서버 1대면 충분, 의존성 없음 / 재시작 시 초기화, 서버 증설 시 서버마다 따로 셈
- 런칭 전 동시 도입: MVP 4개가 실서버에서 다 돌기 전에 붙이면 시연할 배포 결과물과 tool이 호출할 기존 기능이 같이 흔들림
- Kafka 동시 도입: 새 개념이 많고(파티션, consumer group, offset, 멱등성, DLQ) EC2(t3.small 2GB) 메모리 부담. 일정이 12월로 밀림

## 결과
- 새 의존성: Spring AI, Redis(Compose 컨테이너 추가). EC2 t3.small 2GB 메모리 여유 확인 필요
- 착수 시 확인할 것: Spring AI tool 자동 실행 비활성화 방법, tool에 userId를 넘기는 방법(ToolContext 등), Gemini 스타터와 Spring AI 2.0 호환
- Gemini API 키는 서버 환경변수(`.env`, GitHub Secrets, EC2 `.env`)로만. 프론트 호출 금지
- 처음 나오는 개념(tool 호출 루프, userId 주입, 숫자 검증, Redis RateLimiter)은 개발자가 직접 작성 (045)
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 AI 코치에 실행 tool(매수·매도 등)을 추가하거나 LLM이 손익을 직접 계산하는 구조를 제안하지 않는다. 관련: 023, 024, 045.
