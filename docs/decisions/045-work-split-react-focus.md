# 045. 작성 분담 조정: 백엔드는 새 개념만 직접, 반복 로직은 에이전트

## 상태
확정 (2026-11-03)

## 배경
런칭(11/14, 039)까지 11일. 남은 작업 중 프론트 연결(홈, 실시간 차트, 아파트, 계약서, 내 마을)이 가장 많고, 개발자는 React 쪽 학습에 시간을 쓰기로 함.
기존 규칙은 심장 4개(① 매수·매도, ② 평가액, ③ 실거래가 배치, ④ 실시간 차트)를 모두 개발자가 직접 작성하는 것이었음.
심장 ①을 직접 작성하며 `Math.multiplyExact`, `BigDecimal` scale·반올림, 비관적 락, 계층 구조를 이미 익혔고, 남은 백엔드 중 상당수는 같은 패턴의 반복임.

## 결정
백엔드는 처음 나오는 개념이 있는 작업만 개발자가 직접 작성하고, 반복 로직은 에이전트가 작성한 뒤 개발자가 리뷰한다.

| 작업 | 작성 |
| --- | --- |
| 심장 ① 매수·매도 (완료) | 개발자 (수정 시에도 같음) |
| 심장 ② 평가액 계산 | 에이전트 작성 → 개발자 리뷰 |
| 심장 ③ 실거래가 배치 | 개발자 (방향 제시 → 작성 → 교정) |
| 심장 ④ 실시간 평가액 차트 | 에이전트 작성 → 개발자 리뷰 (049로 변경) |
| WebSocket 평가액 푸시 (STOMP 설정·브로드캐스트) | 대화창 소스 → 개발자 직접 입력 → 검토 (새 개념) |
| 추천 API, 집 사기, 그 밖의 도메인 Service·Controller·DTO | 에이전트 작성 → 개발자 리뷰 |
| 프론트 동작 (api, hooks, ws, 데이터 연결, 상태·이벤트) | 기존대로 개발자 (대화창 소스 → 직접 입력 → 검토) |

## 이유
- 새 개념이 없는 반복 로직은 직접 작성해도 학습 효과가 작고, 그 시간을 React 쪽에 쓰는 편이 면접 대비에 유리
- 심장 ③ 배치(외부 API 호출·파싱, 증분 upsert)와 WebSocket은 처음 나오는 개념이고 면접 꼬리질문이 많이 붙는 영역이라 직접 작성 유지
- 심장 ④와 프론트 동작은 React 집중 방향과 일치

## 포기한 대안
- 기존 규칙 유지(심장 4개 모두 직접): 학습 범위 최대 / 일정 위험, React 학습 시간 부족. 포기
- 테스트만 에이전트: 구현은 직접 / 계산 20줄 안팎이라 시간 절약이 작음. 포기
- 백엔드 전부 에이전트(심장 ③ 포함): 시간 최대 절약 / 배치 설계(전체 vs 증분)를 면접에서 설명할 근거가 약해짐. 포기

## 결과
에이전트가 구현과 테스트를 모두 쓰면 스스로 채점하는 구조가 되므로 아래를 지킨다.
- 돈 계산 PR은 개발자가 테스트 1개 이상을 손으로 검산
- PR 보고에 "면접 대비 핵심 3가지"를 넣어, 직접 쓰지 않은 코드도 설명할 수 있게 함
- 에이전트가 쓴 코드의 주석도 짧은 명사형 규칙을 따름
번복 조건: 남은 일정에 여유가 생기거나 개발자가 원하면 해당 작업을 다시 직접 작성으로 돌림.
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 심장 ①③④와 프론트 동작의 구현 코드를 파일에 직접 쓰지 않는다. 관련: 021, 036, 039, 044.
