# 059. Kafka 범위 변경: 체결 이벤트 푸시 → 시세 스트림 기반 보유 종목 하락 알림

## 상태
확정 (2026-11-16)

## 배경
- 053은 체결 이벤트 → 그 회원 평가액 즉시 푸시로 Kafka를 도입하기로 함
- 구현 전 확인: 주문한 탭은 매수·매도 성공 시 `queryKeys.portfolio()` invalidate로 이미 즉시 갱신됨. 053의 효과는 같은 회원의 다른 탭·기기뿐
- 지원 예정 공고(SK주식회사 제조AI Data팀, 마감 11/20) 담당 업무에 Kafka 기반 Application (필수 자격은 아님)

## 결정
- 기능: 가상 시세 tick → Kafka → 보유 종목이 평균 매입가 대비 3% 이상 떨어지면 알림
- 발행: `VirtualPriceProvider.tick()` 끝에서 종목별 가격 발행. 토픽 `stock-price-ticked`, 키 = 종목코드, 파티션 3개, 보관 1일, 비동기 발행
- 소비: 컨슈머 그룹 `price-alert`. 그 종목 보유자 전체 대상, 현재가 ≤ 평균 매입가 × 97%면 알림
- 지난 시세: 발행 후 30초 넘은 메시지는 판정하지 않고 건너뜀
- 알림 저장: DB `notification` 테이블(판정 근거 숫자: 현재가·평균 매입가 스냅샷, 생성 시각, 읽은 시각. 문구는 화면이 만듦, 2026-11-18 변경). 유니크 키 (회원, 종목, 날짜)로 종목당 하루 1번 + 중복 메시지 멱등 처리. 읽어도 삭제 안 함, 사용자 삭제 가능, 7일 지난 알림은 매일 새벽 스케줄러가 삭제
- 실시간: 접속 중이면 `/user/queue/alerts`로 토스트 + 안 읽은 수 푸시 (046 개인 큐 경로 재사용)
- 실패: 재시도 2번 후 DLT(`stock-price-ticked-dlt`). Spring Kafka 4.0부터 기본 이름이 `토픽.DLT` → `토픽-dlt`로 바뀌어 기본값을 따름 (2026-11-19 보강)
- 실서버: 브로커 1대(KRaft) Compose 컨테이너, EC2 t3.small 유지 + Kafka 힙 256MB + 스왑 2GB, AWS Budgets 알림 (2026-11-18 변경: 프리 플랜 계정이라 t3.medium 선택 불가)

## 이유
- 053은 사용자 체감이 거의 없음 (주문한 탭은 이미 즉시 갱신)
- 시세 tick은 계속 나오는 스트림이라 파티션 키, 컨슈머 그룹, 오프셋, 재시도·DLT를 실제로 쓸 일이 생김
- 키 = 종목코드: 같은 종목의 가격 순서 유지
- 비동기 발행: 알림은 부가 기능. 브로커가 죽어도 시세 생성(게임 본체)은 계속 돌아야 함
- 30초 건너뜀: 컨슈머가 밀렸다가 따라잡을 때 지난 가격으로 알림이 몰려 나가는 것 방지
- 알림함을 DB에: Kafka는 메시지 한 건 삭제·읽음 표시가 안 됨. 사용자가 조회·삭제하는 데이터는 DB
- 유니크 키: Kafka는 at-least-once 전달이라 같은 메시지가 두 번 올 수 있음. DB 제약으로 멱등 처리
- 평균 매입가 기준: "내가 산 값보다 떨어졌다"를 바로 이해함

## 포기한 대안
- 053 체결 이벤트 → 평가액 푸시: 범위 작음 / 주문한 탭은 이미 즉시 갱신, 체감 없음
- 체결 이벤트 + Outbox: 발행 유실 방지 패턴 연습 / 받는 쪽에서 할 기능이 없음
- 오늘 시작가 기준 하락: 시장 관점 / 내 손익과 무관해 이해 어려움
- 조건 맞을 때마다 알림: 단순 / tick마다 알림 폭주
- 알림 여부를 메모리 상태로: 빠름 / 재시작·리밸런싱 때 유실·중복 → 판정용 장부는 062에서 메모리로 채택(재시작 때 DB에서 로드), 알림 저장은 DB 유지
- 접속자에게만 토스트(저장 없음): 단순 / 접속 안 한 사람은 못 봄
- 알림을 Kafka 토픽에 보관: 저장소 추가 없음 / 한 건 삭제·읽음 처리 불가
- EC2 t3.medium: 메모리 여유 / AWS 프리 플랜 계정이라 선택 목록에 없음 (2026-11-18 확인)
- c7i-flex.large(4GB, 프리 플랜 선택 가능): 메모리 여유 / 시간당 약 $0.107(도쿄 기준)로 크레딧($98.97) 만료(2027-01-10) 전에 소진, 프리 플랜은 크레딧 소진 시 서버 중단 위험
- 유료 플랜 전환 후 t3.medium: 선택 가능 / 크레딧 넘는 금액 결제

## 결과
- 053 폐기 (대체: 059). 053의 비용 메모는 그대로 유효, 인스턴스 유형은 위 "실서버" 항목으로 변경 (2026-11-18)
- 메모리 예산 (t3.small 1.9GB, 2026-11-18 측정): 기존 사용 약 980MB(backend 464MB, nginx 4MB), Kafka 힙 256MB. 스왑 2GB는 비상용(EBS라 느림). 스왑 사용이 계속되거나 OOM이 나면 인스턴스 유형 다시 논의
- 5초 주기 평가액 푸시(046)는 그대로
- 새 개념(프로듀서, 토픽, 파티션 키, 컨슈머 그룹, 오프셋, 재시도·DLT, 멱등)은 개발자가 직접 작성 (045). 알림함 API·스케줄러 같은 반복 로직은 에이전트 작성 가능
- 화면: 공통 헤더에 종 + 안 읽은 수, 종을 누르면 아래로 펼쳐지는 알림 목록 드롭다운 (별도 PR `feat/app-header`, `design.md`에 기록. 11/17 별도 페이지 대신 드롭다운으로 변경)
- PR 순서: ① ADR·문서·로컬 브로커·의존성 ② 시세 발행 ③-1 컨슈머 판정·저장 ③-2 재시도·DLT·토스트 ④ 알림함 API·7일 삭제 ⑤ 헤더·목록 데이터 연결 ⑥ 실서버
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 알림 조건(평균 매입가 97%, 하루 1번)을 바꾸거나 Kafka 범위를 시세 하락 알림 밖으로 넓히는 제안을 하지 않는다. 관련: 024, 045, 046, 051, 053, 062.
