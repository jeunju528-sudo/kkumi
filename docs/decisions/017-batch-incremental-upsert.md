# 017. 실거래가 배치: 전체 삭제 후 재적재 대신 증분(upsert)

## 상태
확정 (2026-10-03)

## 배경
실거래가 배치가 매번 데이터를 다시 받아 저장해야 함. `House`가 `AptDeal`의 PK를 참조함.

## 결정
증분(upsert) 방식으로 저장한다.

## 이유
- 전체 삭제 후 재적재하면 `AptDeal`의 PK가 바뀌어 `House`의 참조가 깨짐

## 포기한 대안
- 전체 삭제 후 재적재

## 결과
중복 판별 기준이 필요함 (018). 배치 수집 로직은 직접 작성 영역(심장 ③).
이 결정을 번복하려면 먼저 은주와 논의 필요. 에이전트는 `AptDeal`을 삭제 후 재적재하는 방식을 제안하지 않는다. 관련: 003, 018.
