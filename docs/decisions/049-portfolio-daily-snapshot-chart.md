# 049. 손익 차트: 1일 탭 없이 일별 평가액 기록 + 오늘 현재값, 심장 ④는 에이전트 작성

## 상태
확정 (2026-11-06)

## 배경
홈 "내 손익" 카드 시안은 1일·1주·1달 탭과 요일 축 선 그래프. 서버는 평가액을 순간값으로만 계산하고(044), 시세도 현재가·오늘 시작가만 보관(040)해서 과거 평가액을 다시 계산할 수 없음.
- 1일: 화면에 들어온 뒤 받은 WebSocket 값만 누적 가능 (재진입 시 초기화)
- 1주·1달: 그날그날 값을 저장해 두지 않으면 그릴 수 없음

## 결정
- 1일 탭 삭제. 1주(지난 6일 + 오늘)·1달(지난 29일 + 오늘) 두 탭, 기본 1주
- 매일 0시(KST) 회원별 평가액을 `portfolio_snapshot`(회원·날짜 UK, `total_asset`)에 어제 날짜로 기록 (`PortfolioSnapshotScheduler`, cron + `zone = "Asia/Seoul"`)
- 같은 날 기록이 있으면 건너뜀(멱등): 서비스의 `exists` 확인 + DB UK 두 겹. 회원마다 트랜잭션 분리, 한 명 실패해도 계속
- 서버가 꺼져 있어 기록을 놓친 날은 행 없음. 차트는 그 칸에 점을 찍지 않고 앞뒤 점을 직선 연결 (0으로 떨어뜨리지 않음)
- `GET /api/portfolios/me/history?period=WEEK|MONTH` → 어제까지의 `[{date, totalAsset}]`. 마지막 칸(오늘)은 WebSocket 평가액(046)으로 5초마다 갱신
- 심장 ④(손익 차트)와 이 기록 백엔드는 에이전트가 작성 → 개발자 리뷰 (045 조정). 심장 ①③은 그대로 개발자 작성

## 이유
- 과거 시세를 저장하지 않으므로 거래내역으로 과거 평가액을 역산할 수 없음 → 결과(평가액)를 그날 저장하는 것이 유일한 방법
- 0시 값 = 어제 마감 값. 오늘 값은 이미 WebSocket으로 오므로 오늘 행은 저장하지 않음
- 놓친 날을 현재값으로 채우면 사실과 다른 기록이 남음. 빈칸이 더 정직함
- 1일 탭은 화면 재진입마다 초기화되어 의미가 약하고, 1주·1달이 "인생역전" 흐름을 보여주기에 적합 (개발자 판단)
- 기록·차트 모두 새로 배울 이론이 적다고 개발자가 판단, 일정(11/13 버퍼) 보호

## 포기한 대안
- 1일 탭만(화면 누적): 백엔드 변경 없음 / 재진입 시 초기화, 1주·1달 불가. 포기
- 놓친 날을 기동 시 현재값으로 채움: 선이 매끈함 / 그날 값이 아님. 포기
- 기록 행을 매시간 저장: 1일 탭 가능 / 행 수 24배, MVP에 불필요. 포기
- 거래 시점마다 평가액 저장: 거래 없는 날은 시세 변동이 반영 안 됨. 포기

## 결과
런칭 직후에는 기록이 1~2일치뿐이라 1주·1달 선이 짧음 (감수, 기록 없으면 안내 문구). 0시 정각에는 시세 갱신과 같은 스케줄러 스레드(1개)를 쓰므로 회원 수가 많아지면 기록 시간만큼 시세 갱신이 밀림 (지금 규모에서 무시, 늘면 스레드 풀 분리 검토).
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 빈 날을 임의 값으로 채우지 않는다. 관련: 040, 044, 045, 046.
