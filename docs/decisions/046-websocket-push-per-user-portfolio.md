# 046. WebSocket 푸시: 사용자별 평가액을 서버가 계산해서 개인 큐로

## 상태
확정 (2026-11-06)

## 배경
평가액은 5초 폴링(`usePortfolioQuery` refetchInterval)으로 갱신 중. MVP ②는 WebSocket(STOMP) 실시간 갱신.
푸시 대상을 전 종목 시세(브로드캐스트)로 할지, 사용자별 평가액으로 할지 정해야 함 (README "미정").

## 결정
서버가 5초마다 접속 중인 사용자별로 `PortfolioService.getMyPortfolio`를 호출해 `/user/queue/portfolio`로 보낸다. 화면은 받은 값을 `setQueryData`로 캐시에 넣기만 한다. 메시지마다 바로 반영(throttle 없음, 5초 간격이라 불필요).

## 이유
- 돈 계산을 서버 한 곳(`PortfolioCalculator`, 044)에만 둠. 화면 계산과 서버 값이 어긋날 위험 없음
- 홈·내 거래·종목 목록이 같은 캐시(`['portfolio', 'me']`)라 메시지 하나로 세 화면 갱신
- 인증은 기존 쿠키 필터 재사용: handshake 요청에 accessToken 쿠키가 실려 Principal(memberId)로 개인 큐 주소가 정해짐

## 포기한 대안
- 전 종목 시세 `/topic` 브로드캐스트 + 화면 계산: 접속자 수와 무관하게 메시지 1개 / 평가액 계산이 프론트로 넘어가 044와 충돌. 포기
- 폴링 유지: 구현 없음 / MVP ② 요구(WebSocket)와 다르고 접속자마다 5초마다 HTTP 요청. 포기

## 결과
접속자 × 5초마다 회원·보유 종목 DB 조회 2번 (감수, 소수 접속 기준).
번복 조건: 동시 접속이 늘어 DB 부하가 보이면 보유 종목 캐싱 또는 시세 브로드캐스트로 전환 검토.
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 평가액 계산을 프론트로 옮기는 제안을 하지 않는다. 관련: 029, 040, 044.
