# 047. 아파트 추천 조회: 원 단위 저장, 지역명 컬럼, 살 수 있는 집 비싼 순

## 상태
확정 (2026-11-06)

## 배경
추천 API(`GET /api/apartments`)를 실거래가 배치(심장 ③)보다 먼저 만들게 되어(039, 045 일정 조정), 배치와 맞물리는 값을 먼저 정해야 했음.
- 국토부 거래금액은 만원 단위 문자열("82,500"), `AptDeal.price` 주석은 "원/만원 미정"
- 국토부 응답에 시군구 코드만 있고 이름이 없음. 화면은 "강원 태백시"를 보여주고 지역명으로 검색함
- 최근 6개월 전국 거래는 수만~수십만 건이라 전부 내려줄 수 없음

## 결정
- 거래금액은 원 단위 `long`으로 저장. 배치가 만원 × 10,000으로 변환 (019)
- `AptComplex.regionName`(예: 강원 태백시) 컬럼 추가. 배치가 단지를 만들 때 시군구 코드표로 채움
- 기본 목록은 살 수 있는 집(평가액 ≥ 집값 × 40%)만 비싼 순, 20건씩(Slice). `affordableOnly=false`면 못 사는 집 포함 싼 순. 검색어는 단지명·지역명·법정동 부분 일치
- 내 돈 = 집값 × 40% 원 미만 올림. 조회 조건(집값 ≤ 평가액 × 100 ÷ 40 내림)과 카드 판정이 같은 경계가 되도록 함
- 평가액·현금은 `PortfolioService` 값을 그대로 사용 (044)

## 이유
- 금액 단위를 원으로 통일해 평가액·현금과 바로 비교 (변환 실수 방지)
- 지역명을 DB에 두어야 이름 검색을 쿼리 한 번으로 처리
- 비싼 순: 내 돈으로 살 수 있는 가장 좋은 집부터 보여주는 게 인생역전 톤에 맞음. 못 사는 집은 싼 순이라 "조금만 더 벌면 살 집"이 먼저 보임
- 올림: 내림이면 조회 조건(집값 × 40 ≤ 평가액 × 100)과 판정(내 돈 ≤ 평가액)이 1원 차이로 어긋날 수 있음. 실제 거래가는 만원 단위라 결과 차이는 없음

## 포기한 대안
- 만원 단위 저장: 국토부 값 그대로 / 평가액(원)과 비교할 때마다 변환 필요. 포기
- 조회 때마다 코드 → 이름 변환: 컬럼 없음 / DB에서 이름 검색 불가. 포기
- 살 수 있는 집 싼 순: 단순 / 소형 저가 거래만 먼저 보여 고르는 재미가 없음. 포기
- 단지별 묶음(단지당 1장): 목록이 깔끔 / 014(최근 거래 목록에서 층·가격을 골라 삼)와 다름. 포기

## 결과
한 단지의 거래가 많으면 목록 앞쪽을 차지할 수 있음 (감수, 플레이 테스트 후 검토).
`regionName`이 NOT NULL이라 배치는 단지 생성 시 코드표에 없는 시군구를 만나면 실패 처리가 필요함 (배치 작업 때 결정).
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 거래금액을 만원 단위로 저장하는 제안을 하지 않는다. 관련: 014, 015, 019, 044.
