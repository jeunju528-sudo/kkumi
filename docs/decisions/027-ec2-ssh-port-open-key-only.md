# 027. EC2 SSH 접근: IP 제한, SSM 대신 22번 포트 공개 + 키 인증만

## 상태
확정 (2026-10-06)

## 배경
CD 2단계는 GitHub Actions가 EC2에 SSH로 접속해 `docker compose pull` → `up -d`를 실행하는 방식이다 (026에서 이미지는 GHCR에 올리고 EC2는 pull만 하기로 함). 현재 보안 그룹(kkumi-ec2-sg)은 22번 포트를 개발자 IP만 허용해서, GitHub Actions 서버는 접속할 수 없다.

## 결정
22번 포트를 전체(0.0.0.0/0)에 열고, 접속은 SSH 키 인증만 허용한다. 비밀번호 로그인은 사용하지 않는다. 배포용 키는 개발자 접속용 키와 분리해서 새로 만든다.

## 이유
- Actions 서버 IP를 특정할 수 없어서 IP 제한이 불가능함 (아래 대안 참고)
- 키 인증만 허용하면 키 없이는 접속할 수 없음. 개인키는 GitHub Secrets에만 보관
- 새 개념·새 AWS 서비스 없이 SSH + Secrets만으로 구현됨. 10/24 고정 일정과 새 기술 상한선(024)에 맞음
- 이 서비스는 가짜 돈 게임이고 EC2에 보관하는 비밀값은 `.env`(DB 정보, API 키)뿐임. 노출 시 피해 범위가 제한적임

## 포기한 대안
- GitHub Actions IP 대역만 허용: 가장 좁게 여는 방식 / Actions IP 대역은 수천 개 규모에 자주 바뀌고, 보안 그룹은 규칙 개수 한도(기본 인바운드 60개)가 있어 넣을 수 없음. 구조적으로 불가능해서 포기
- SSM Run Command: 22번 포트를 열 필요가 없어 가장 안전함 / EC2 IAM 역할, SSM 에이전트, Actions용 AWS 자격증명 등 새 개념이 한 번에 늘어남. 일정상 보류하고 런칭 후 전환 검토
- EC2가 주기적으로 pull(cron 등): 22번 포트 불필요 / 배포 시점과 실패가 Actions 화면에서 보이지 않아 디버깅이 어려움

## 결과
22번 포트가 공개되므로 봇의 무차별 접속 시도가 로그에 쌓임 (감수). 키 없이는 뚫리지 않지만, 아래를 지켜야 안전함.
- 비밀번호 로그인 꺼짐 확인 (EC2에서 `sudo sshd -T | grep -i passwordauthentication` 결과가 `no`)
- 배포 전용 키를 따로 만들어 GitHub Secrets에만 보관, 키를 채팅·레포에 올리지 않음
- 후속 과제: 런칭 후 SSM 전환 검토 (22번 포트 닫기)

이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 개인키·비밀번호를 채팅이나 레포에 노출하지 않고, 22번 포트를 열어 둔 채 비밀번호 인증을 켜자고 제안하지 않는다. 관련: 001, 024, 026.
