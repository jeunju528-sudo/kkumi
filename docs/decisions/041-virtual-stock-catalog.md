# 041. 가상 종목 카탈로그: 유형 배치, 시작가, 호가 단위, market 삭제

## 상태
확정 (2026-10-27)

## 배경
ADR 029에서 종목 유형 3종(안정형 8 / 롤러코스터형 8 / 한방형 4)과 "종목별 호가 단위로 반올림"을 정했지만, 종목별 유형 배치, 시작가, 호가 단위표는 구현 시점으로 미뤘다 (`domain/stocks.md`). `Stock.market`(KOSPI/KOSDAQ)은 실제 종목을 쓰던 설계에서 남은 필드다.

## 결정
- 유형 배치
  - 안정형: 마르덴전자, 다이온모터스, 제노텔레콤, 아르카홀딩스, 유르파트너스, 칼리건설, 시벨푸드, 데니마트
  - 롤러코스터형: 세르반반도체, 쿠르텍, 브론델배터리, 벨라전기차, 카르넬게임즈, 트리아엔터, 라미로보틱스, 모르조선
  - 한방형: 도르빈바이오, 소티제약, 아젤뷰티, 펠로항공
- 시작가: 프론트 목업(`StockSearchPage`)의 가격을 그대로 쓴다. 시작가는 평균 회귀 기준가이며 `Stock.basePrice`에 저장한다. 종목별 값은 `domain/stocks.md`
- 호가 단위: 국내 주식 가격대별 호가 단위표(2023년 1월 개편 기준)로 가격에서 계산한다. 종목에 저장하지 않는다

| 가격 | 호가 단위 |
| --- | --- |
| 2,000원 미만 | 1원 |
| 2,000원 이상 5,000원 미만 | 5원 |
| 5,000원 이상 20,000원 미만 | 10원 |
| 20,000원 이상 50,000원 미만 | 50원 |
| 50,000원 이상 200,000원 미만 | 100원 |
| 200,000원 이상 500,000원 미만 | 500원 |
| 500,000원 이상 | 1,000원 |

- `Stock.market` 필드와 `Market` enum을 삭제한다
- 종목 데이터는 서버가 뜰 때 `StockDataInitializer`가 DB에 없는 코드만 넣는다

## 이유
- 업종 이미지(바이오는 한방, 반도체·2차전지·게임은 롤러코스터, 통신·지주·유통은 안정)와 유형이 맞아 이름만 봐도 성격이 짐작됨
- 목업 가격은 화면에서 이미 써 온 값이고, 20개 모두 해당 가격대의 호가 단위로 나누어떨어짐
- 호가 단위를 가격에서 계산하면 가격이 구간을 넘을 때 단위도 자동으로 바뀜 (실제와 같은 방식)
- `market`은 화면·도메인 어디에서도 쓰지 않음

## 포기한 대안
- 모든 종목 10원 단위: 단순 / 60만원대 종목이 10원씩 움직여 어색함
- 종목별 호가 단위 컬럼: 가격대가 바뀌어도 단위가 고정되어 실제와 다름
- `market` 유지: 스키마 변경이 없음 / 의미 없는 필수 컬럼이 남음

## 결과
- `ddl-auto: update`는 컬럼을 지우지 않으므로 로컬 DB와 RDS에서 `ALTER TABLE stock DROP COLUMN market;`을 직접 실행해야 함. RDS는 이 변경이 배포되기 전에 실행
- 호가 단위표 중 기사로 확인한 구간은 1,000~2,000원(1원), 10,000~20,000원(10원), 100,000~200,000원(100원), 200,000~500,000원(500원), 500,000원 이상(1,000원). 나머지 구간은 원문 확인 기록 없음. 게임용이라 실제와 달라도 동작에는 문제 없음
- 시작가와 유형 배치는 플레이 테스트 결과로 조정할 수 있음 (이 ADR 갱신)
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 실제 기업명이나 실제 시세에서 가져온 시작가를 제안하지 않는다 (020). 관련: 020, 029, 040.
