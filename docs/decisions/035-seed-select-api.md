# 035. 시드 선택 API: 중복 가입은 409, 다 쓴 signupToken 쿠키는 삭제

## 상태
확정 (2026-10-13)

## 배경
신규 회원은 카카오 로그인 후 `signupToken` 쿠키(임시 토큰, Path `/api/members/seed`)를 받고 시드 선택 화면으로 간다(033). 시드머니를 고르면 실제로 회원 행을 만들고 정식 토큰을 발급하는 API가 필요했다. 같은 카카오 계정으로 두 번 가입 요청이 오는 경우(뒤로 가기 후 재제출, 버튼 연타)와, 가입 후 남는 임시 토큰을 어떻게 처리할지 정해야 했다.

## 결정
- `POST /api/members/seed`, 요청 본문 `{"seedMoney": "SMALL" | "LARGE"}` (`SeedRequest`)
- `signupToken` 쿠키에서 kakaoId·닉네임을 꺼내 `MemberService.join`으로 가입하고 memberId를 받는다
- 이미 가입한 kakaoId면 `BusinessException(ALREADY_JOINED)` → `GlobalExceptionHandler`가 409와 `{code, message}`로 응답
- 성공하면 같은 응답에서 `accessToken` 쿠키 발급(`setHeader`)과 `signupToken` 쿠키 삭제(`addHeader`, 같은 이름·Path에 `Max-Age=0`)를 함께 내려보낸다. 응답 본문은 없음(200)
- 이동(`/home`)은 서버 리다이렉트가 아니라 프론트가 200을 받은 뒤 처리

## 이유
- 중복 가입은 요청 형식이 아니라 현재 상태(이미 회원 있음)와 충돌하는 상황이라 400보다 409가 의미에 맞다. 프론트는 `code`로 "이미 가입됨 → 홈으로" 분기만 하면 된다
- 임시 토큰은 가입 한 번에만 쓰는 값이라 가입 직후 지운다. 남겨두면 10분 동안 같은 토큰으로 재요청이 가능하고 브라우저에 쓸모없는 쿠키가 남는다
- 서버는 브라우저 쿠키를 직접 지울 수 없어서, 같은 이름·Path로 만료된 쿠키를 덮어쓰는 방식만 가능하다. Path가 다르면 다른 쿠키로 취급되어 지워지지 않는다
- 쿠키 2개를 한 응답에 보내므로 두 번째는 `addHeader`. `setHeader`는 같은 이름의 `Set-Cookie` 헤더를 덮어쓴다
- API는 JSON 요청(fetch)으로 호출되므로 리다이렉트보다 상태 코드로 결과를 알려주는 편이 프론트에서 다루기 쉽다

## 포기한 대안
- 중복 가입이면 기존 회원으로 로그인 처리(200): 사용자 입장에서는 매끄럽지만 이미 고른 시드머니와 다른 값이 들어와도 조용히 무시하게 되어 원인 파악이 어려움. 포기
- 중복 가입 400: 요청 자체는 올바른 형식이라 의미가 맞지 않음. 포기
- `signupToken`을 만료(10분)까지 두기: 구현은 간단하지만 재사용 가능 시간이 남음. 포기
- 성공 시 서버가 `/home`으로 302: fetch 요청에서는 리다이렉트가 화면 이동으로 이어지지 않음. 포기

## 결과
- 409 응답, 쿠키 발급·삭제는 자동 테스트 없이 시드 선택 화면 연결 때 브라우저에서 수동 확인한다(036)
- 동시에 두 요청이 들어오면 둘 다 `existsByKakaoId`를 통과할 수 있다. 이 경우 `kakao_id` 유니크 제약으로 DB에서 막히고 지금은 500으로 나간다. 가입은 1회성이라 런칭 범위에서는 감수한다
- `signupToken` 쿠키가 없으면 Spring 기본 처리로 400(`MissingRequestCookieException`)
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 중복 가입을 200으로 처리하거나 signupToken을 남겨두는 방식을 먼저 제안하지 않는다. 관련: 031, 033, 034.
