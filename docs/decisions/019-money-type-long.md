# 019. 금액 타입: 원 단위 long, 평균 매입가만 BigDecimal

## 상태
확정 (2026-10-03)

## 배경
금액을 어떤 타입으로 다룰지 정해야 했음.

## 결정
금액은 원 단위 `long`으로 다룬다. 평균 매입가만 `BigDecimal`을 쓴다.

## 이유
- 평균 매입가는 나눗셈 결과라 소수점이 생긴다. 정수 `long`으로 두면 소수점이 버려져 오차가 쌓이므로 `BigDecimal`을 쓴다
- 그 외 금액(현금, 주가, 집값, 손익)은 원 단위 정수라 `long`으로 충분하다

## 포기한 대안
- 금액 전부 `BigDecimal` (이 프로젝트에서 비교한 기록은 없음)
- `double` / `float` (이진 부동소수점 오차 때문에 금액에 쓰지 않는다)

## 구현 시 정할 것
- 평균 매입가의 scale과 `RoundingMode`는 매수·매도 구현(심장 ①) 때 정하고 ADR에 덧붙인다

## 결과
`double` / `float`는 CLAUDE.md에서 금지이며 엔티티·DTO는 `ArchitectureTest`가 검사한다.
이 결정을 번복하려면 먼저 은주와 논의 필요. 에이전트는 금액에 `double` / `float`를 쓰지 않는다.
