# 021. 범위: 기능 추가보다 프론트 직접 구현 우선

## 상태
확정 (2026-10-03)

## 배경
런칭일(2026-10-24)이 고정이라 일정이 밀리면 기능을 줄여야 함. 풀스택 포지션도 지원하는 상황이라, 기능 개수와 프론트 구현 경험 중 무엇을 우선할지 정해야 했음.

## 결정
기능을 하나 더 추가하는 것보다 프론트를 직접 구현하는 것을 우선한다. 프론트 동작(api, hooks, ws, 상태·이벤트 로직)은 은주가 직접 작성한다.

## 이유
- 풀스택 지원이라 기능 하나 더보다 프론트를 직접 짠 경험이 중요

## 포기한 대안
- 기능 추가 우선 (구체적인 장단점은 기록 없음)

## 결과
자연어 검색은 10/17까지 MVP 4개가 실서버에서 동작할 때만 10/18~20에 추가하고, 아니면 런칭 후로 미룬다.
이 결정을 번복하려면 먼저 은주와 논의 필요. 에이전트는 프론트 동작 코드를 대신 작성하지 않고 방향 제시와 리뷰만 한다 (CLAUDE.md "프론트 분담"). 관련: 024.
