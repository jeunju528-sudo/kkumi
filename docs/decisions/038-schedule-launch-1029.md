# 038. 일정 재조정: 런칭 10/24 → 10/29, 범위 유지

## 상태
폐기 (대체: 039, 2026-10-25 런칭 11/14로 재조정)

## 배경
심장 ①(매수·매도)이 계획(10/10~12)보다 약 5일 늦어짐. 인증 작업(카카오 로그인 → JWT → 성공 핸들러 → 쿠키 필터 → 시드 선택)이 새 개념이 많아 계획 2일에서 실제 6일(10/7~10/13)이 걸림. 기존 원칙은 "런칭일 고정, 밀리면 기능을 줄임"(021, 024)이었음.

## 결정
런칭일을 2026-10-29로 옮기고 기능은 줄이지 않는다. 자연어 아파트 검색, 거래내역 조회·내 거래 화면 연결, 계약서·변신 연출, 도감, 캡처 화면 다듬기 모두 유지. 자연어 검색은 게이트(10/27)에서 MVP 4개가 실서버에서 동작하면 10/28에 추가한다. 10/29는 더 이상 옮기지 않는다.

## 이유
- 설명 우선 원칙(개발자가 모든 코드를 면접에서 설명)을 지키면서 하루 6~7시간 기준으로 남은 작업을 넣을 수 있는 최소 기간
- 거래내역은 매수·매도 때 `TradeHistory`가 이미 저장되고(011) 화면도 만들어져 있어(032) 조회 API와 연결만 남음
- 10/19 중간 점검으로 지연을 일찍 확인

## 포기한 대안
- 10/24 유지 + 기능 축소: 일정은 지킴 / 거래내역·연출·자연어 검색이 빠져 결과물이 줄어듦
- 런칭일 미정: 압박이 없어짐 / 마감이 없으면 범위가 계속 늘어남

## 결과
버퍼일이 없음 (10/28은 자연어 검색 + 통합 테스트). 10/19 중간 점검에서 매수·매도가 실서버 화면에서 동작하지 않으면 그때 일정을 다시 논의한다. 021, 023, 024, 031, 036에 적힌 10/17·10/19·10/21·10/24 날짜는 당시 기준이며 이 문서로 대체.
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 개발자와 논의 없이 기능 축소나 런칭일 변경을 진행하지 않는다. 관련: 021, 023, 024, 032.
