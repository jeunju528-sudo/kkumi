# 040. 가상 시세 현재가: 메모리 + 1분 주기 DB 저장

## 상태
확정 (2026-10-27)

## 배경
ADR 029에서 서버가 5초마다 모든 종목 가격을 갱신하기로 했다. 현재가를 어디에 두고 서버가 재시작될 때 어떻게 이어갈지는 구현 시점으로 미뤘다. main에 merge할 때마다 자동 배포로 서버가 재시작되므로 재시작은 자주 일어난다.

## 결정
현재가는 서버 메모리에 두고 5초마다 갱신한다. 1분마다 현재가와 오늘 시작가(일일 제한폭 기준)를 DB `stock` 테이블에 저장한다. 서버가 뜰 때 DB에 저장된 값으로 메모리를 채우고, 저장된 값이 없으면 시작가(`basePrice`)에서 시작한다.

## 이유
- 매수·매도·평가액 계산은 메모리 값을 읽으므로 시세 때문에 DB 조회가 늘지 않음
- 재시작해도 마지막 저장 시점(최대 1분 전) 가격에서 이어져, 배포할 때마다 평가액이 시작가 기준으로 튀지 않음
- 서버 1대라 메모리 한 곳이 기준이 됨. 새 저장소가 필요 없음 (024)
- 쓰기 횟수: 5초마다 저장하면 하루 345,600번(20행 × 17,280회), 1분마다면 28,800번

## 포기한 대안
- 메모리만: 가장 단순 / 배포마다 모든 종목이 시작가로 돌아가 사용자 평가액이 갑자기 바뀜
- 갱신할 때마다 DB 저장: 재시작 손실 없음 / 쓰기 횟수 12배, 나중에 갱신 주기를 줄이기 어려움
- Redis: 서버 여러 대일 때 유리 / 새 기술 상한선(024)에 걸리고 서버 1대라 이득 없음

## 결과
- 재시작하면 마지막 저장 후 최대 1분의 가격 변동이 사라짐 (감수). 그 사이 체결가는 거래 이력에 남아 있음. 정상 종료(배포 재시작)는 종료 직전에 한 번 더 저장해 손실 없음 (2026-10-29 보강, `ContextClosedEvent`). 강제 종료는 최대 1분 손실 그대로
- 서버 날짜(KST)가 바뀌면 오늘 시작가를 그 시점 현재가로 바꿈
- `Stock`에 현재가·오늘 시작가 컬럼을 추가하는 구현은 시세 PR 3에서 진행. `Stock` 주석의 "현재가는 저장 X"는 이 결정으로 바뀜
- 구현 때 `price_date`(오늘 시작가의 날짜) 컬럼도 추가 (2026-10-29 보강). 자정을 넘겨 재시작하면 저장된 오늘 시작가가 어제 값이라, 날짜로 구분해 어제 값이면 저장된 현재가를 오늘 시작가로 씀. 세 컬럼은 null 허용(기존 행은 null = 저장 전 → 시작가에서 시작)
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 Redis 같은 새 저장소나 갱신마다 DB에 저장하는 방식을 제안하지 않는다. 관련: 024, 029.
