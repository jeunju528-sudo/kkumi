# 043. 화면 가드: 회원 조회 실패면 시작 화면

## 상태
확정 (2026-10-29)

## 배경
`docs/ui-spec.md`의 가드 규칙은 "미로그인 → `/`, 로그인했지만 시드 미선택 → `/seed`"였고, 프론트 `MemberResponse`에 `hasSelectedSeed`가 있었다. 회원 조회 API(`GET /api/members/me`)를 만들면서 이 두 상태를 서버가 구분할 수 있는지 확인했다.
- 시드를 고르기 전에는 회원 행이 없다. `Member.join`이 시드머니를 필수로 받고, 그 전 단계는 임시 토큰(`signupToken`)으로만 이어간다 (031, 035)
- `signupToken` 쿠키는 Path가 `/api/members/seed`라 `/api/members/me` 요청에 실리지 않고, HttpOnly라 프론트도 읽을 수 없다 (033)
- 회원 행이 있으면 시드는 반드시 고른 상태라 `hasSelectedSeed`는 항상 true

## 결정
화면 가드는 한 가지 규칙만 둔다. `/`, `/seed`를 뺀 화면은 `GET /api/members/me`가 실패하면(401, 404) `/`로 보낸다. `MemberResponse`에서 `hasSelectedSeed`를 뺀다.

## 이유
- 서버가 실제로 구분할 수 있는 상태는 "회원 있음 / 없음" 두 가지뿐
- 시드 선택 중에 나간 사용자는 `/`에서 카카오 로그인을 다시 누르면 서버가 신규 회원으로 판단해 `/seed`로 보낸다 (033의 로그인 성공 처리). 별도 분기 없이 기존 흐름으로 돌아옴
- 쿠키·토큰 구조를 바꾸지 않음

## 포기한 대안
- `/api/members/me`가 `signupToken`까지 확인해 "가입 대기" 상태를 응답: 프론트가 바로 `/seed`로 보낼 수 있음 / `signupToken` Path를 넓혀야 해서 033을 번복하고, 임시 토큰이 실리는 요청이 늘어남. 얻는 것은 카카오 버튼 한 번 덜 누르는 것뿐이라 포기

## 결과
- 시드 선택 화면에서 새로고침 없이 다른 화면으로 이동하면 `/`로 돌아간다. 임시 토큰 만료(10분) 전이라도 카카오 로그인을 다시 거친다 (감수)
- `MemberResponse`의 `tier`, `houseCount`는 집 도메인 작업(집 사기 PR)에서 추가한다
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 `signupToken` Path를 넓히거나 `hasSelectedSeed`를 다시 추가하는 제안을 하지 않는다. 관련: 031, 033, 035.
