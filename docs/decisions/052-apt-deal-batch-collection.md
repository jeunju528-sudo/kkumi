# 052. 실거래가 배치 수집: 전국 시군구 코드표, 매일 2개월 재수집, JSON 응답

## 상태
확정 (2026-11-10)

## 배경
실거래가 배치(심장 ③, 003·017·018)를 구현하면서 수집 범위, 주기, 응답 형식, 지역명 출처를 정해야 했음.
- 국토부 "아파트 매매 실거래가 상세 자료" API는 시군구 코드(LAWD_CD) + 계약 연월 단위로만 조회. 전국 일괄 조회 없음
- 응답에 시군구 이름이 없음 (047 `regionName` NOT NULL)
- 일일 호출 한도 10,000회 (개발계정)

## 결정
- 수집 범위: 전국 시군구 256개. 코드·이름은 `resources/apartment/sigungu.csv` 정적 파일
- 코드표 생성 규칙: 법정동코드 전체자료(행정표준코드관리시스템)에서 "존재"인 시군구 단위만. 구가 있는 시는 상위 시를 빼고 구 코드만. 이름은 시·도 약칭 + 나머지(예: 강원 태백시, 광주 목포시), 세종은 "세종시"
- 주기: 매일 1번 이번 달 + 지난달 재수집. `apt_deal`이 비어 있으면 최근 7개월(시세 6개월 + 이번 달)
- 응답 형식: `_type=json` + 기존 Jackson. 응답 필드는 전부 `String`으로 받고 변환은 코드에서
- 면적: `setScale(2, HALF_UP)` 후 조회·저장 (유니크 키 018과 컬럼 scale 2 일치)
- 코드표에 없는 시군구가 응답에 나오면 그 건만 건너뛰고 `log.warn` (047에서 미룬 결정)
- 저장 단위: (시군구, 월)마다 트랜잭션 분리. 한 단위가 실패해도 나머지 계속
- 스케줄러 스레드 2개 (`spring.task.scheduling.pool.size`). 배치 I/O 동안 시세 갱신이 멈추지 않도록
- 첫 적재는 `ApplicationReadyEvent`에서 별도 스레드(`apt-deal-initial`)로 시작. 같은 이벤트에서 시세 엔진이 종목을 메모리에 올리므로 메인 스레드를 오래 묶지 않음
- 첫 적재와 매일 수집의 동시 실행 방지: `AtomicBoolean` (서버 1대 전제. 여러 대면 DB 락·ShedLock 필요)

## 이유
- 전국: 시드 500만이면 첫 집값 상한이 약 1,250만 원이라 지방 소도시 거래가 꼭 필요
- 이번 달 + 지난달: 신고 기한이 계약 후 30일이라 지난달 거래가 늦게 들어오고, 해제 표시도 나중에 붙음
- 호출 수: 첫 적재 약 1,800회, 매일 약 500회 + 1,000건 초과 시 페이지 넘김 (예: 화성 동탄구 2026-05 1,428건). 한도 안
- 정적 파일: 행정구역은 몇 년에 한 번 바뀜. 외부 호출·테이블보다 의존이 적고 diff로 변경 확인 가능
- JSON: 의존성 추가 없음. XML은 JDK 파서(코드 길어짐) 또는 jackson-dataformat-xml(패키지 추가, 024)
- 전부 `String`: 같은 필드가 숫자·문자로 섞여 옴 (`jibun` 1338 / "1003-2")
- 면적: 응답은 소수 3~4자리(84.858, 83.7457). 반올림 없이 조회하면 저장된 값과 안 맞아 유니크 키 위반
- 스레드 2개: `@Scheduled` 기본 스레드는 1개라 배치 호출 동안 시세 갱신·평가액 푸시가 멈춤. 시세·평가액 기록·배치는 서로 다른 데이터를 다루고, 같은 작업끼리는 겹치지 않음

## 포기한 대안
- 수도권만 수집: 호출 수 적음 / 500만 시드는 첫 집을 못 삼
- 법정동코드 API 실시간 호출: 항상 최신 / 키·실패 지점 추가
- 코드 → 이름 Java 상수: 컴파일 검사 / 코드가 데이터로 뒤덮임
- XML 파싱: 기본 형식 / 위 이유
- 스케줄러 1스레드 유지 + 새벽 실행: 변경 없음 / 첫 적재 때 시세 10분 이상 멈춤
- 배치만 `@Async` 별도 스레드: 배치만 분리 / 새 개념·설정 추가

## 확인한 것 (2026-11-10)
- 전남·광주 통합(전남광주통합특별시, 코드 12)과 화성·부천 구 설치 후 옛 코드(46110, 29110, 41590, 41190)는 2026-05·08·10 모두 0건. 새 코드로 과거 거래까지 조회됨 (`aptSeq`에는 옛 코드가 남음)
- 빈 값은 공백 한 칸(" "), 해제는 `cdealType` "O", 거래 없는 달은 `"items":""`, 1건이면 `item`이 객체
- 로컬 첫 적재 (2026-11-11): 248,133건, 시군구 255개(마지막 코드 52800까지), 2026-05~11 월 3.3만~4.9만 건(11월은 진행 중 6,198건), 최저가 800만 원

## 결과
- 행정구역이 바뀌면 코드표를 같은 규칙으로 수동 재생성 (감수)
- 첫 적재 중 실패한 (시군구, 월)은 3개월 이상 지난 달이면 매일 재수집 범위 밖이라 다시 받지 않음 (감수, 로그로 확인)
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 수집 범위를 줄이거나 XML 파싱으로 바꾸는 제안을 하지 않는다. 관련: 003, 015, 017, 018, 024, 047, 049.
