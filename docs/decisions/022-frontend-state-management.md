# 022. 프론트 상태 관리: Redux·Zustand 대신 TanStack Query + Context

## 상태
확정 (2026-10-03)

## 배경
프론트의 서버 데이터와 클라이언트 상태를 어떻게 관리할지 정해야 했음.

## 결정
서버 데이터는 TanStack Query로, 클라이언트 전용 상태는 Context(`useContext`)와 `useState`로 관리한다. Redux·Zustand 같은 전역 상태관리 라이브러리는 쓰지 않는다.

## 이유
- 꿈이의 데이터는 대부분 서버 데이터(보유 종목, 시세, 집 목록)
- 클라이언트 전역 상태는 로그인 회원 정도라 Context로 충분
- 써본 경험이 있고 서버 데이터 캐싱·로딩·재요청이 자동임
- WebSocket 실시간 값도 `setQueryData`로 같은 캐시에 합칠 수 있음

## 포기한 대안
- Redux·Zustand: 전역 상태를 일원화할 수 있음 / 보일러플레이트가 많고 서버 데이터 캐싱을 직접 구현해야 함

## 결과
클라이언트 전역 상태는 Context로 따로 관리해야 함 (감수).
이 결정을 번복하려면 먼저 은주와 논의 필요. 에이전트는 Redux, Zustand 등 전역 상태관리 라이브러리를 도입하지 않는다 (ESLint가 import를 막음). 관련: 024.
