# 061. 런칭 후 확장: AI 자산 코치 + Elasticsearch 두 개로 확정, 자연어 검색·골든셋 제외

## 상태
확정 (2026-11-18)
보강 (2026-11-26): Elasticsearch 용도를 단지명 자동완성에서 관제 로그 저장으로 변경 (064)

## 배경
- 런칭 후 과제에 AI 자산 코치(051), 자연어 아파트 검색(023), AI 응답 평가 골든셋, Elasticsearch 자동완성이 함께 있었음
- 자연어 검색은 AI 코치와 같은 Spring AI + Gemini를 사용해 새 기술 경험이 늘지 않음
- AI 코치의 "아파트 추천" tool이 "지금 돈으로 살 수 있는 집" 같은 자연어 질문을 일부 처리함
- 골든셋은 자연어 검색 정확도 평가용이라 자연어 검색을 빼면 대상이 없음
- Elasticsearch는 백엔드 채용 공고 기술 스택에 Kafka·Redis와 함께 자주 등장하는 별도 기술

## 결정
런칭 후 확장은 Kafka(059) 다음 AI 자산 코치(051) → Elasticsearch 단지명 자동완성 순서로 두 개만 진행한다. 자연어 아파트 검색(023)과 골든셋은 하지 않는다.

## 이유
- 기능 하나당 새 기술 하나: AI 코치 = Spring AI·Gemini·Redis, 자동완성 = Elasticsearch
- 자연어 검색의 핵심 사용 장면은 AI 코치 아파트 추천 tool로 대체 가능
- Elasticsearch 범위: 단지 마스터만 인덱싱(거래 행 제외), nori 한글 형태소 분석. "MySQL LIKE로도 되지만 형태소·부분 일치 때문에 붙였다"로 설명

## 포기한 대안
- 자연어 검색 + Elasticsearch 둘 다: 검색 기능이 둘로 나뉨 / 자연어 검색은 새 기술 없음, 일정 증가
- 자연어 검색만: 023 설계 재사용 / 새 기술 경험 없음
- 골든셋을 AI 코치 평가로 전환: AI 품질 측정 소재 / 범위 증가, 이번에는 제외

## 결과
- 024 예외 추가: Elasticsearch (단지명 자동완성 한정)
- 착수 전 확인: EC2 메모리(t3.medium 4GB에 Spring·Kafka·Elasticsearch 동시 구동), 힙 크기, 인덱스 동기화 방식(배치 후 재색인 vs 증분). 구현 단계에서 확정
- 023은 폐기 (대체: 061)
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 자연어 아파트 검색이나 골든셋을 다시 제안하지 않는다. 관련: 023, 024, 051, 059.
