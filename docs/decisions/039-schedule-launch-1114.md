# 039. 일정 재조정: 런칭 10/29 → 11/14, 범위 유지

## 상태
확정 (2026-10-25)

## 배경
038에서 런칭을 10/29로 옮긴 뒤, 10/16~10/25 동안 개발을 진행하지 못함 (10/24 코스콤 필기시험 준비). 10/25 기준 끝난 것은 10/15 작업(심장 ① 엔티티 계산, 037)까지이고, 남은 작업은 노션 일정 기준 15일치. 남은 기간 4일(10/26~29)로는 MVP ① 실서버 동작까지만 가능.

지금까지 실제 소요가 계획의 약 1.3~1.5배였음 (인증 계획 2일 → 실제 6일, 시드 선택 화면 계획 10/10 → 실제 10/14, 심장 ① 계획 2일 → 10/15에도 진행 중).

## 결정
런칭일을 2026-11-14로 옮기고 기능은 줄이지 않는다. 남은 15일치 작업을 10/26~11/14(20일)에 배치하고, 처음 하는 연결 작업(심장 ①, 가상 시세, 종목·매매 화면, 실시간 차트, 아파트 추천)에 하루씩 버퍼를 둔다. 자연어 아파트 검색은 게이트(11/11)에서 MVP 4개가 실서버에서 동작하면 11/13에 추가한다.

## 이유
- 남은 작업 15일 × 실제 소요 배율 1.3 ≈ 20일. 10/26 시작 기준 11/14
- 038과 같은 기준(설명 우선 원칙 유지, 하루 6~7시간)으로 범위를 그대로 넣을 수 있는 최소 기간
- 038은 버퍼가 없어 한 번 밀리면 바로 재조정이 필요했음. 이번에는 버퍼를 일정 안에 넣음

## 포기한 대안
- 10/29 유지 + 기능 축소: 일정은 지킴 / 평가액·WebSocket·아파트 추천·집 사기가 빠져 MVP 4개 중 1개만 남음
- 계획 일수 그대로(11/9): 5일 빠름 / 지금까지 실제 속도를 반영하지 않아 다시 밀릴 가능성이 높음

## 결과
11/1 중간 점검(매수·매도 실서버 화면 동작)에서 밀렸으면 그때 일정을 다시 논의한다. 038의 10/19·10/27·10/28·10/29 날짜는 이 문서로 대체.
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 개발자와 논의 없이 기능 축소나 런칭일 변경을 진행하지 않는다. 관련: 021, 023, 024, 038.
