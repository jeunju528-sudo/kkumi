# 029. 가상 시세 변동 방식: 랜덤 워크 + 평균 회귀 + 시장 공통 요인

## 상태
확정 (2026-10-06)

## 배경
ADR 020에서 시세를 서버가 만드는 가상 시세로 정했다. 외부 시세 데이터를 쓸 수 없으므로 가격이 어떻게 움직일지를 직접 정해야 한다. 조건은 다음과 같다.
- 사람들이 재미있게 할 수 있을 것 (평가액이 출렁이고 캡처해서 자랑할 만할 것)
- 금액대가 시작가에서 너무 멀어지지 않을 것 (개발자 요청)
- 개발자가 면접에서 원리를 설명할 수 있을 정도로 단순할 것

## 결정
서버가 일정 주기마다 모든 종목의 가격을 한 번에 갱신한다. 한 번 갱신할 때의 변동률은 아래 세 가지를 더해서 만든다.
- 시장 공통 요인: 그 시점의 "장 분위기". 모든 종목에 같은 방향으로 작용하고 종목마다 민감도가 다름
- 종목 고유 랜덤: 종목별 변동성에 따라 크기가 달라지는 무작위 값 (랜덤 워크)
- 평균 회귀: 시작가(기준가)에서 멀어질수록 기준가 쪽으로 약하게 끌어당기는 힘

세부 규칙은 다음과 같다.
- 모든 사용자가 같은 값을 본다. 서버 한 곳에서 만들고 WebSocket으로 푸시한다
- 종목 성격은 3종으로 나눈다: 안정형(변동성 작음), 롤러코스터형(변동성 큼), 한방형(평소엔 작고 낮은 확률로 급등락 이벤트)
- 급등락 이벤트는 가격 모델 안에서만 처리한다. 뉴스 문구 같은 화면 연출은 시안에 없으므로 MVP에서 제외
- 장 시간 없이 24시간 갱신한다
- 기준 시점 대비 상하한을 둔다 (초기안: 서버 날짜(KST) 시작 가격 대비 ±30%)
- 가격은 `long` 원 단위이고 종목별 호가 단위로 반올림한다
- 갱신 주기, 변동성, 이벤트 확률, 평균 회귀 강도는 설정값(`application.yaml`)으로 둔다. 갱신 주기 초기안은 5초이고 나머지 숫자는 기록 없음. 구현 후 플레이 테스트로 정한다
- 수수료와 호가 스프레드는 없다 (도메인 규칙). 그래서 매수 직후 매도의 손익은 갱신 주기 사이 변동폭 안으로 제한된다

## 이유
- 랜덤 워크는 가격 변동을 설명하는 기본 개념이라 면접에서 설명하기 쉬움
- 평균 회귀로 금액대가 유지되고 가격이 한쪽으로 끝없이 도망가지 않음
- 시장 공통 요인이 있으면 종목들이 같이 오르내려서 평가액이 크게 출렁이고 "오늘 장 분위기"라는 이야기가 생김
- 서버 한 곳에서 만들면 모든 사용자가 같은 값을 봐서 캡처 비교가 의미를 가짐
- 외부 시세 데이터를 쓰지 않음 (ADR 020)

## 포기한 대안
- 실제 종가로 끝나도록 경로를 만드는 방식(브라운 다리 등): 실제 종가가 필요해서 외부 데이터 사용 불가 (`failures/002`)
- 사용자별 독립 랜덤: 같은 종목이 사람마다 다른 값이라 캡처 비교와 공정성이 깨짐
- 미리 짜둔 시나리오 재생: 구현은 쉬움 / 금방 반복되어 재미가 떨어짐

## 결과
- 현재가 저장 방식(메모리 + 주기적 DB 스냅샷 등)과 서버 재시작 시 복구는 구현할 때 정하고 ADR로 남김. `Stock` 엔티티 주석 "현재가는 저장 X"와 충돌할 수 있어 구현 시 확인 필요
- 구현체는 `stock/`의 `StockPriceProvider` 구현체로 만든다
- 이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 실제 시세 데이터를 가상 시세의 보정 입력으로 쓰자고 제안하지 않는다 (ADR 020). 관련: 020.
