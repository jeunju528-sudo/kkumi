# 011. 보유 현황: 거래 이력 합산 대신 현황 테이블도 함께 저장

## 상태
확정 (2026-10-03)

## 배경
평가액을 WebSocket으로 계속 다시 계산해야 해서 현재 보유 상태를 바로 읽을 수 있어야 함.

## 결정
보유 현황(`StockHolding`)과 거래 이력(`TradeHistory`)을 둘 다 저장한다.

## 이유
- 평가액을 계속 다시 계산하므로 현재 상태를 바로 읽는 쪽이 유리함
- 이력만 두면 계산할 때마다 전체를 합산해야 하고 평균 매입가 계산이 복잡해짐

## 포기한 대안
- 거래 이력 합산(이력만 저장): 데이터가 하나라 관리가 단순함 / 평가액 계산마다 전체 합산, 평균 매입가 계산이 복잡

## 결과
두 테이블의 정합성을 관리해야 함. 매수·매도는 트랜잭션 안에서 둘을 함께 갱신한다 (감수). 매수·매도 계산은 직접 작성 영역(심장 ①).
이 결정을 번복하려면 먼저 은주와 논의 필요. 에이전트는 보유 현황 없이 이력 합산만으로 평가액을 계산하는 방식을 제안하지 않는다.
