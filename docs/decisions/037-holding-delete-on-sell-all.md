# 037. 보유 종목: 전량 매도 시 행 삭제, 거래 수량 1 이상

## 상태
확정 (2026-10-15)

## 배경
매수·매도(심장 ①) 구현 전, 전량 매도 후 `StockHolding` 행을 남길지와 거래 수량의 최솟값을 정해야 했음.

## 결정
전량 매도로 수량이 0이 되면 `StockHolding` 행을 삭제한다. 매수·매도 수량은 1 이상만 허용한다.

## 이유
- 행이 있으면 보유 중이라는 의미가 단순해짐. 평가액 계산(심장 ②)·보유 목록 조회에서 `quantity > 0` 필터가 필요 없음
- 다시 매수하면 새 행이 생겨 평균 매입가가 자연스럽게 체결가부터 시작함
- 거래 기록은 `TradeHistory`에 남으므로 행을 지워도 이력은 유지됨 (011)
- 수량 검사는 두 곳: 요청 DTO `@Min(1)`(입력 오류를 Controller 앞에서 400), 엔티티 `INVALID_QUANTITY`(Service 경로와 무관한 최종 방어)

## 포기한 대안
- 수량 0 행 유지: 행 재사용으로 insert/delete가 줄어듦 / 모든 보유 조회에 수량 필터 필요, 재매수 시 평균가 초기화를 따로 처리해야 함

## 결과
전량 매도 후 재매수 시 행 id가 바뀜 (감수). 회원+종목 유니크 제약(`uk_holding_member_stock`)은 그대로 유지.
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 수량 0인 보유 행을 남기는 방식이나 수량 0 이하 거래를 허용하는 방식을 제안하지 않는다. 관련: 011, 019, 025.
