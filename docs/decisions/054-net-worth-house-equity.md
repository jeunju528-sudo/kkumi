# 054. 순자산: 평가액 + 내 집 지분(구매가 40%), 홈 카드는 오늘 증감과 자산 구성

## 상태
확정 (2026-11-12)

## 배경
- 홈 카드 큰 숫자가 평가액(현금 + 주식)이고 아래 줄이 총손익(평가액 − 시드머니, "시드머니 대비")이었음
- 집을 사면 현금에서 집값 40%가 빠지는데 집은 어디에도 잡히지 않아, 집을 산 것만으로 손실처럼 보임 (예: 시드 500만에서 -69.2%)
- 인생역전 게임에서 집을 산 순간이 가장 자랑할 때인데 숫자는 반대로 보여 캡처 바이럴과도 어긋남
- 평가액은 집 추천 기준(평가액 ≥ 집값 × 40%)이라 정의를 그대로 바꿀 수 없음

## 결정
- 평가액(현금 + 주식 평가액)은 그대로 두고 집 추천·첫 집 목표에만 사용
- 순자산 = 평가액 + 내 집 지분. 내 집 지분 = 산 집마다 `HousePriceRule.ownAmount(구매가)`(집값 × 40%, 원 미만 올림)의 합
- 총손익 = 순자산 − 시드머니 (= 실현손익 + 평가손익, 집 사기 전후 변화 0)
- 홈 카드: 순자산(큰 숫자) + 오늘 증감(어제 마감 순자산 대비) + 자산 구성 막대(부동산·주식·현금 %)
- 시드머니 대비 숫자는 홈 카드에서 빼고 내 마을 자랑 줄로 이동 ("시드 500만원 → 순자산 4,542만원, 9.1배 인생역전")
- 일별 기록(`portfolio_snapshot`)에 `house_equity` 컬럼 추가, 차트·오늘 증감은 순자산 기준

## 이유
- 집 지분을 결제 금액과 같은 규칙으로 계산하면 집을 산 순간 순자산 변화가 원 단위까지 0. 숫자가 정직하고 설명하기 쉬움
- 가짜 대출 60%를 빚으로 함께 잡으면 집값 100% − 대출 60% = 40%로 같은 값. 회계상 순자산 정의와도 맞음
- 집값 변동·집 팔기는 MVP 밖이라 구매가 기준 지분이 바뀌지 않음
- 오늘 증감은 이미 있는 어제 마감 기록(049)으로 계산 가능해서 새 저장 없이 실시간 맛을 살림
- 자산 구성 막대로 현금 비중이 보이면, 결제가 현금 기준이라 "주식을 팔아야 집을 산다"는 규칙이 화면에서 바로 이해됨

## 포기한 대안
- 평가액 정의 자체에 집 포함: 이미 산 집으로 다음 집이 추천되고 현금이 없어 "주식 팔러 가기"만 뜨는 꼬인 상태. 포기
- 집값 100%를 순자산에 포함: 집 사는 순간 자산이 뛰어 병맛은 살지만, 가짜 대출만큼 손익이 부풀어 "시드 대비 +300%" 같은 엉터리 손익. 포기
- 기록 컬럼 `total_asset`의 의미를 순자산으로 바꿈: 컬럼 이름과 의미가 어긋나 설명이 어려움. 포기
- 순자산 컬럼(`net_worth`)을 따로 추가: `ddl-auto: update`가 기존 행을 0으로 채워 차트가 0으로 떨어짐. 지분 컬럼은 기존 행 0이 실제 값(집 사기 도입 전)과 같아서 지분 컬럼 쪽 선택

## 결과
- 평가액과 순자산 두 기준이 공존. 화면마다 어느 쪽인지 용어 사전(`domain/glossary.md`)으로 구분
- 어제 마감 기록이 없으면(가입 첫날) 오늘 증감은 null → 화면에 "오늘이 첫날이에요"
- 평가액 조회 1번에 쿼리 2개 추가(집 구매가, 어제 기록). WebSocket 푸시도 같은 메서드라 틱마다 접속자 수만큼 늘어남. 런칭 규모에선 문제없음, Kafka(053) 도입 때 다시 점검
- `portfolio` → `apartment`(`HousePriceRule`), `house`(`HouseService`) 의존 추가. `apartment` → `portfolio`(추천 API)와 패키지 순환이 생기지만 빈 순환은 없음
- 운영: 배포 후 RDS에서 `house_equity` 컬럼 추가와 기존 행 0 확인 필요
- 집값 변동·집 팔기 도입 시 지분 계산 기준(구매가 vs 현재 시세) 재검토
이 결정을 번복하려면 먼저 개발자와 논의 필요. 에이전트는 평가액(집 추천 기준)에 집 지분을 넣거나 순자산에 집값 100%를 넣지 않는다.
