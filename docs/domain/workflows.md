# 주요 업무 흐름

사용자가 거치는 주요 흐름. 용어는 `glossary.md`, 선택 이유는 `docs/decisions/` 참고.
규칙의 최종 기준은 CLAUDE.md "도메인 규칙 (확정)". 화면 구성은 `docs/design.md`.

## 1. 가입과 시드 선택
1. 카카오 로그인 (유일한 로그인 방식, ID/비밀번호 없음)
2. 가입 직후 시드머니를 선택 (500만원 / 5,000만원, 1회)
3. 홈으로 이동

## 2. 주식 매수·매도 (심장 ①)
1. 종목 목록에서 종목을 골라 사기·팔기 화면으로 이동
2. 매수는 현금으로만 가능
3. 매수·매도는 한 트랜잭션에서 보유 종목(`StockHolding`)과 거래 이력(`TradeHistory`)을 함께 갱신 (ADR 011)

## 3. 평가액·손익 실시간 갱신 (심장 ② ④)
1. 시세를 `StockPriceProvider`로 조회 (ADR 020). 서버가 만드는 가상 시세이고 모든 사용자가 같은 값을 봄 (ADR 029)
2. 평가액(현금 + 주식 평가액)을 계산 (`portfolio/`)
3. WebSocket(STOMP)으로 프론트에 푸시
4. 프론트는 `src/ws/`에서 구독하고 `setQueryData`로 쿼리 캐시에 반영
- 미정: 전체 브로드캐스트 vs 보유 종목만 푸시, 메시지마다 리렌더 vs throttle (`docs/decisions/README.md` "미정")

## 4. 아파트 추천 (심장 ③)
1. 실거래가 배치가 하루 1번 국토부 데이터를 받아 증분(upsert)으로 저장 (ADR 003, 017, 018)
2. 최근 6개월 실거래 목록을 시세로 사용 (ADR 014, 015)
3. 평가액이 집값 × 40% 이상인 집을 추천
4. 카드 버튼은 3가지 상태: 현금 충분 → "계약하기" / 평가액은 되지만 현금 부족 → "주식 팔러 가기" / 평가액도 부족 → "N원 모자라요"

## 5. 집 사기
1. 현금이 충분한 카드에서 "계약하기"를 누름. 현금이 모자라면 사용자가 직접 주식을 팔아 현금을 만든 뒤 진행 (자동 매도 없음)
2. 현금에서 집값의 40%를 차감하고 집(`House`)을 생성
3. 계약서 연출 (도장 찍기, 변신 알림, 자랑하기 버튼)
4. 내 마을(도감)에 집이 추가되고, 보유 집 수로 변신 단계를 다시 계산
5. 주식은 그대로 유지 (포트폴리오 초기화 없음)

## 일정이 밀릴 때 줄이는 순서
계약서 연출 → 변신 연출 → 도감 빈 슬롯. 화면 자체는 유지한다 (`docs/design.md`).
